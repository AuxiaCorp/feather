# Feather Language — 独立セルフホスティング・ブートストラップ（v8、実験版）

このフォルダーは、Rustや外部依存関係を必要としない、新しいFeatherコンパイラー・ブートストラップ用のソースツリーです。V7言語のすべての機能を置き換えるものではありません。機能の同等性が確立されるまでは、動作するV7アーカイブを別途保持してください。

## 検証済みの実行可能な機能

コンパイラーの実装は `src/compiler.feather` にあります（Featherブートストラップのサブセット、約2,300行）。トークンと行の認識、数値オペランドのデコード、前方・後方分岐の構造的な解決を行い、x86-64機械語命令とLinux ELF64ヘッダーを直接出力します。

x86-64ネイティブのシード（`bootstrap/feather-seed`）は、このFeatherソースを2つ目のネイティブコンパイラーにコンパイルします。生成されたコンパイラーは同じソースから3つ目を生成します。各世代はバイト単位で同一で、SHA-256ダイジェストも同一です。

### `.feather -> .fthr`

このブートストラップにおける `.fthr` は、以前のV7 `FTHRNAT2` コンテナーではなく、`.fthr` 拡張子を持つLinux ELF64実行ファイルです。ELFはOSネイティブのコンテナーであるため、プログラムはLinux上で直接実行されます。

ビルドや実行にインタープリター、Rust、Cargo、Python、Clang、GCC、LLVM、glibc、JVMは必要ありません。Windows、ARM64、およびV7形式との互換性はまだ実装されていません。

最初の行には `#terminal-only`、`#executable`、`#script` のいずれかが必須です。最後の行は `quit.script` とし、その後に改行を付けます。3つのモードは現在、同じコンソール向けLinux ELFエントリーモデルを生成します。GUI/ウィンドウ権限のセマンティクスは未実装です。

### ELFとセキュリティ

ELFは静的リンクされ、動的ローダーを持たず、読み取り/実行セグメントと読み取り/書き込みセグメントが分離され、スタックは実行不可です。現在のELFは `ET_EXEC` で、PIE/ASLRには対応していません。ユーザーコード用のサンドボックスはありません。

レジスター演算ではラップアラウンド方式の64ビット整数を使用します。完全な型システムや自動境界チェックはありません。

## コンパイラツールチェーンなしでビルド

Linux x86-64で、このフォルダーから実行します。

```sh
./scripts/build.sh
./scripts/test.sh
./bin/feather examples/hello.feather examples/hello.fthr
./examples/hello.fthr
```

または：

```sh
make build
```

必要なのは、ビルド済みのx86-64機械語シード、Featherソース、Linux標準システムコールだけです。任意のシェルビルド/テストスクリプトはbashと基本的なシステムユーティリティを使用します。実行時に言語コンパイラツールチェーンへの依存はありません。これはクロスプラットフォームのブートストラップではありません。

### インストール

`~/.local/bin` にインストールするには：

```sh
./scripts/install-linux.sh
```

別のインストール先には `PREFIX=/custom/path` を設定します。

ネイティブCLIは現在、2つの位置引数を受け取ります。

```sh
feather SOURCE.feather OUTPUT.fthr
```

`feather build --maximum`、`feather inspect`、`feather lib` などのV7完全版コマンドはまだ移植されていません。未対応引数での `./bin/feather` 呼び出しはサポートされません。

## 実装済みのブートストラップ構文

文法は意図的に限定されています。

```feather
#terminal-only
Working=demo
set r01=0000000000000000
set r02=0000000000000003
while r01<r02 [
say"Hello"
inc r01
]
quit.script
```

変数は `r00..r99` という100個の64ビットレジスタースロットに限定されます。`set` が受け付けるのは小文字の16進数字ちょうど16桁です。V7の `set enabled=true` のような任意の識別子にはまだ対応していません。

操作：`copy r01=r02`、`inc r01`、`dec r01`、`add r01=r02`、`sub r01=r02`、`mul r01=r02`。

条件：`when r01==r02 [`、`when r01!=r02 [`、`when r01<r02 [`、`when r01>=r02 [`。

ループ：`while r01<r02 [`、`while r01!=r02 [`、`while r01==r02 [`。ブロックは単独行の `]` で閉じます。

### 出力、ファイル、バイナリーバッファー

- `say"ASCII/UTF-8 text"` — エスケープシーケンスを解釈せず、文字列内の引用符も扱わずにテキストを出力します。
- `load source` — argv入力を固定ソースバッファーに読み込み、バイト長を `r00` に設定します。
- `store output rXX` — 次のargvパスにバイナリー出力を書き込みます。
- `get r01=source[r02]` — 1バイトを読み込みます。
- `get32 r01=output[r02]` — 32ビット値を読み込みます。
- `put output[r01]=r02` — 1バイトを書き込みます。
- `put32 output[r01]=r02` — 32ビット値を書き込みます。
- `put64 output[r01]=r02` — 64ビット値を書き込みます。
- `append r01="48454c4c4f"` — 小文字の16進数で指定したバイト列を追加します。
- `fail` — 終了ステータス2で終了します。

1行につき1ステートメントです。改行はLFで、最終行もLFで終わる必要があります。行頭の `""` コメントと `Working=...` 構文が認識されます。一般的なV7構文はまだ移植されていません。

これは移行用の文法サブセットであり、Feather構文との完全な互換性を主張するものではありません。

## コンパイラーのアーキテクチャ

コンパイラーはFeatherで記述され、セルフホスティングできますが、現在は直接的な1パスの低レベル変換（direct one-pass lowering）を行います。汎用AST、セマンティックアナライザー、オプティマイザー、ジェネリック型、IRはまだ実装されていません。

## 検証

`./scripts/test.sh` は、3世代のセルフビルドのバイト単位の一致、ネイティブELF実行、実行時の算術演算とループ、32/64ビットのバイナリーバッファー操作、NULおよび `0xff` を含むファイルコピー、ファイルI/Oエラー、不正なソースコードの拒否、実行不可スタックのメタデータを検証します。Rustや他言語のコンパイラーは使用しません。

### シードと信頼の起点

シードは信頼の起点となる事前コンパイル済み機械語プログラムです。最初はこのソースツリーの外部で用意されました。初回ビルド後は、以前にセルフビルドしたFeather実行ファイルを使用して、`src/compiler.feather` からコンパイラーを再現可能な形で生成できます。

世代間のハッシュ一致は、テスト対象アーキテクチャで決定的に再生成できることを示します。ただし、悪意ある動作がないこと、メモリー安全性、本番環境向けの強化を証明するものではありません。

## 残されている重要な移行作業

歴史的な機能を維持するため、古いV7アーカイブを保存してください。ネイティブself-hostブランチは、名前付き変数/Bool/テキスト式、完全なlexer/AST/型システム/IR、型付き数値幅、ソース位置付き診断、符号付きオーバーフローチェック、GCなしのメモリー安全性保証、自動境界チェック、async、パッケージマネージャー/98ライブラリー、`Number.by`、TLS/ネットワーク、GUI/Blender/3D、FFI、`FTHRNAT2` 形式、署名、ARM64、Windows、ファジング/セキュリティレビューにはまだ対応していません。

**信頼できないソースコード向けの信頼できるコンパイラーとして、このバージョンをデプロイしないでください。** これは検証済みのネイティブself-host基盤であり、本番利用可能な言語ディストリビューションではありません。
